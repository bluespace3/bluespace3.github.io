## 📝 今日概要

自动化测试框架的「全链路打通」之日——从鸿蒙设备识别到 App 侧全自动登录，一口气解决了 7 个阻塞性问题，核心突破在于用引擎层拦截绕过了 AI 模型的内置安全策略限制。

## 🔍 核心技术进展

**1. App 侧全自动登录闭环（最核心）**
- 问题链：未登录 → 模型输出 `Take_over` → 框架跳过 → 卡死；密码框触发 `FLAG_SECURE` → 截图全黑 → 模型拒绝操作
- 终方案：三层架构——引擎层拦截 `Take_over` 自动重写为登录步骤；检测黑屏时通过 ADB `type_text_robust()` 直接输入密码并发送上帧正常截图；提示词层英文硬覆盖模型内置安全规则
- 设计了完整的凭据优先级体系：用例步骤 > 设置页兜底（可选）> 不填不触发

**2. 鸿蒙设备识别 + Windows 进程环境继承修复**
- 根因：Electron 启动时冻结了父进程 PATH，后续用户修改的环境变量无法渗透
- 方案：从 Windows 注册表 `HKCU\Environment` 实时读取完整 PATH，自动发现 `hdc.exe`

**3. 失败日志智能化改造**
- 按用例 ID 去重统计失败次数（合并重复条目）
- 按 TAPD 负责人过滤（普通用户只看自己的，admin 看全部）
- AI 疑似 Bug 筛选默认开启，传统 UI + AI 自动化双覆盖
- 企微日报移除失败明细，仅保留汇总和链接

**4. TAPD 人员体系入库**
- `users` 表新增 `tapd_user_id` + `display_name`，CSV 启动时自动同步
- 打通用例负责人 → 登录账号 → 中文名 三层映射

**5. CI 报告链接缺失修复**
- 根因：CI 上传格式 `{平台}-{环境}-{时间}.html` 与日报解析器不匹配
- 补充正则解析规则，15 份存量报告立刻可用

**6. 多个底层 Bug 修复**
- `buildAllureManifest` 未导入 → 步骤 4 裁判崩溃
- `execSync` 走 `cmd.exe` 超时 → 改用 `spawn` 直调 + 重试机制
- `get_message` 误删 import → token 统计崩溃
- PC 用例加号点击过快（30-80ms 间隔）→ 改为轮询等待数值变化

## 💡 深度洞察与经验教训

- **洞察**：AI Agent 自动化的最大瓶颈不是模型能力，而是**模型内置安全策略与业务需求的冲突**。AutoGLM 的 FLAG_SECURE 停手行为是训练级硬编码，提示词压不住——真正的解法是「不让模型看到黑屏」，在引擎层静默完成操作。这是「AI 可控性」问题的一个经典案例。

- **教训①**：Electron 进程的环境变量继承是 Windows 自动化中的隐形坑。用户改了 PATH 但 IDE 没感知到，这类问题排查耗时且反直觉——「命令行能用但程序里不行」时，第一时间应检查进程环境继承链。

- **教训②**：`execSync` 在 Windows 上走 `cmd.exe` 中间层，设备忙时 10 秒就 ETIMEDOUT。凡涉及 ADB/外部设备的同步调用，应一律改用 `spawn` + 参数数组 + 合理超时 + 重试。

- **教训③**：文件名格式不匹配是「数据存在但看不到」类 bug 的典型根因。CI 上传和本地解析用的是两套命名约定，如果没有集成测试覆盖，很容易在重构后悄悄断裂。
