### 🌐 Nginx 端口冲突排查（来源：TUI 会话，19:30-19:38）
- **问题**：Nginx 无法启动，6521 端口被 SSH 远程端口转发（`-R 6521`）占用
- **链路还原**：外部 → 6521(Nginx) → xxx.xxx.xxx.xxx:6522(SSH 反代隧道) → Mac，但 SSH `-R 6521` 配合 `GatewayPorts yes` 导致 SSH 直接监听 `xxx.xxx.xxx.xxx:6521`，与 Nginx 冲突
- **定位手段**：`ss -tlnp | grep 6521`、`pstree -p`、`ps -fp` 逐层追踪到来自 Mac 的 SSH 会话
- **解决方案**：Mac 端将 `-R 6521:...` 改为 `-R 6522:...`，释放 6521 给 Nginx

### ⚙️ Cron 任务模型白名单修复（来源：飞书会话，09:07-09:35）

## 💡 深度洞察与经验教训

- **洞察**：SSH 远程端口转发 + Nginx 反代的端口规划需要提前约定。当 `GatewayPorts yes` 开启时，`-R` 转发会监听 `xxx.xxx.xxx.xxx`，容易与其他服务冲突。**建议**：SSH 反代统一使用内部端口（如 6522），Nginx 占用对外端口（如 6521），各司其职。

- **教训**：`openclaw config patch` 的 dry-run 模式会报一些不相关的 schema 校验警告，但不代表 patch 本身有问题。实际执行时应信任 patch 内容而非被 dry-run 噪音误导。

- **教训**：周末 AI 新闻采集效率极低（0 条），cron 策略需要增加"周末模式"——或放宽时间窗口至 72h，或直接跳过周日。
