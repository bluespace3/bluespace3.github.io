### 1. 🏗️ 自动化测试全链路可观测体系（核心突破）

今天最大的产出是围绕 `test_failure_record` 表构建了一整套观测面板：

| 模块 | 技术方案 | 亮点 |
|---|---|---|
| **AI 自动化总览** | Electron 客户端内嵌面板 | 失败记录上报 + 误报率始终展示 |
| **传统 UI 总览** | 独立 HTML 面板（无鉴权） | 覆盖率按固定回归基线（272）× 测试服分子 |
| **运行失败日志专页** | 独立页面，复用双源 API | 传统 PC + AI 失败合一展示，默认筛「未解决」 |

关键设计决策：覆盖率放弃动态查询用例库，改用**固定回归基线表**（22 模块 / 272 条），避免了 RC 服重复统计和模块名对不齐的顽疾。平台从 APP 合并拆为 Android / iOS / PC 分列，解决了 177 + 165 = 342 的假数据问题。

### 2. 📣 企微日报系统（从零上线）

一条完整的日报流水线：**数据聚合 → LLM 智能判定 → 企微推送 → 可视化配置**

- 统计源：UI（`ui_auto_test_case`）+ AI（`test_plan_executions`）双线汇总
- LLM 分析：`qwen-vl-max` 视觉模型读截图 + 日志，判定疑似 Bug
- 定时任务：动态 cron（配置页保存即刷新），不重启即可改发送时间
- 超长 markdown 自动拆分发送

配套实现了**网页配置界面**（在失败日志页右上角），支持在线编辑 Webhook URL、模型 Key、发送模板，所有配置持久化到 `data/wecom/daily-report-config.json`。

### 3. 🐛 三枚硬核 Bug 定位与修复

| Bug | 根因 | 修复 |
|---|---|---|
| **PC UnicodeDecodeError** | `subprocess.run(text=True)` 未指定 encoding，PYTHONIOENCODING=utf-8 下用 UTF-8 解 GBK 输出炸了 | 加 `encoding="utf-8", errors="replace"` |
| **日报 AI 统计全 0** | Electron 写 `partial_failure`，后端白名单只有 `failed` → 整条执行记录被跳过 | 补全 `failure` / `partial_failure` / `partial` |
| **ECharts 图表压扁** | 容器 `display:none` 时 `echarts.init`，宽度为 0 | 先 `setLoading(false)` 再用双 `requestAnimationFrame` 延迟初始化 + ResizeObserver |

## 💡 深度洞察与经验教训

- **洞察**：「统计数据口径」是测试平台最脆弱的一环。今天暴露了三层不一致 —— 时间字段含义不一致（`updated_at` ≠ 执行时间）、状态枚举不一致（`failure` ≠ `failed`）、平台合并逻辑不一致（APP ≠ Android + iOS）。根因都是**多个独立模块各自定义了一套约定**，缺乏统一的数据契约。后续应在写入端就统一枚举值，而非在读取端拼命兼容。

- **教训①**：远程 SSH 执行 psql 时，PowerShell 的引号转义是反复踩的坑（今天至少失败了 3 次）。**正确做法**：永远用 `scp` 传 SQL 文件 + `psql -f`，不要在命令行内联 SQL。

- **教训②**：ECharts 在隐藏容器中初始化的问题，本质是「DOM 渲染时机」与「JS 执行时机」的时序竞争。通用解法：**渲染图表前确保容器已 visible，用 `requestAnimationFrame` 等待布局完成，再 attach ResizeObserver 兜底**。

- **教训③**：企微日报首次发送成功，但 LLM 判定全部 403。原因是部署机 `.env` 中 `OPENAI_API_KEY` 权限/配额问题。**部署环境的环境变量管理需要更严格的 checklist**，不能假设「本地能跑远程就能跑」。
