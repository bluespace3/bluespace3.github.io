## 📝 今日概要

基建维护日——修了 Prisma 迁移卡死、Web 自动化 URL 环境映射错乱、Chrome Profile 重复拷贝拖慢用例执行等一串历史债务，顺带发现了赛博日记定时任务自身的架构缺陷。

## 🔍 核心技术进展

**1. 赛博日记定时任务架构问题定位** *(来自 main session)*
- 根因：`generate-cyber-journal.sh` 通过 shell 调用 `openclaw agent` CLI，形成 agent → shell → CLI → agent 的嵌套链路
- 表现：CLI 调用经常超时（300s 限制），失败后回退逻辑直接复制原始素材，导致日记变成任务执行报告

**2. Excel 回归用例批量整理** *(来自 Cursor)*
- 用 Python pandas 筛选 77 条标签为"待整理"的 PC 用例，自动在目录 `回归-稳定的/` 后插入 `/PC/`
- 导出独立 Excel 供后续使用，处理了文件占用冲突的边界情况

**3. Prisma 迁移修复** *(来自 Cursor)*
- 解决 TS2353 类型错误：schema 已有 `retryCount`/`retryWaitSeconds` 但 Prisma Client 未重新生成
- 解决运行时 `column does not exist`：迁移未应用到数据库
- 解决 `web_url_route` 唯一索引迁移卡死：先去重重复行，再 `prisma migrate resolve --rolled-back` 回滚状态后重新执行

**4. Web 自动化 URL 环境映射修复** *(来自 Cursor)*
- 同一页面标题对应多环境 URL 时，原逻辑按字典序取第一个，可能命中非当前环境
- 修复：收集所有候选 URL，优先匹配 hostname 与运行环境标识一致的项；标题别名合并时同样优先当前环境

**5. Chrome Profile 预热缓存方案设计** *(来自 Cursor)*
- 问题：每条测试用例独立启动 Python 进程，每次都重新精简拷贝 Chrome User Data
- 方案：Electron 启动时预热一次拷贝到缓存目录，用例执行时直接复用

**6. Git 分支合并与冲突解决** *(来自 Cursor)*
- dev/main → dev/test 合并，解决 `plan-merge-report-builder.ts`（统一报告依赖）和 `TestPlanView.vue`（移除作用域外变量引用）的冲突

## 💡 深度洞察与经验教训

- **洞察**：「字典序取第一个」是多候选选择中的隐性 Bug 来源。只要候选列表的排序不反映业务优先级（如环境偏好），就会在特定数据排列下触发错误。这类问题在单环境测试中不会暴露，多环境上线后才炸。
- **教训**：Prisma schema 改了字段 ≠ 类型定义和数据库同步了。三件事（schema、generate、migrate）必须作为一个原子操作完成。以后改 schema 后立即 `generate` + `migrate deploy`，不要拆到不同提交。
- **教训**：定时任务中嵌套调用 CLI agent 是脆弱架构。agent → shell → CLI → agent 链路中任何一环超时或返回异常格式都会导致后续处理失败。正确做法是让 cron 的 agentTurn 直接读文件、处理、写文件。
- **教训**：数据库唯一索引迁移失败后，Prisma 不会自动回滚，后续所有迁移都被阻塞。必须手动 `resolve --rolled-back` 后重新执行。
