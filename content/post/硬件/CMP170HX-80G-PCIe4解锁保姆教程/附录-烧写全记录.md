# CMP 170HX -> A100-80G: FF Burn Record

Complete record of the fuseless-fuse (FF) burns that unlocked this card,
performed via voltage fault injection (VFI) on a self-built RP2040 PWMVID
glitcher. Read this before attempting any further burns.

The RP2040 glitcher firmware itself is NOT part of this release. The burns
below only require the burn-window register state; how you reach it is up
to you -- the bundled `ga100vfi/` and `pico-ga100vfi/` public VFI toolchains
are the recommended starting point (see "Burn-window prerequisites").

## Card identity

| Field | Value |
|---|---|
| SKU | CMP 170HX 8GB (Hynix HBM) |
| PCI ID | 10de:20c2 |
| BDF | 0000:01:00.0 |
| Die | GA100 (PMC_BOOT_0 = 0x170000A1) |
| VBIOS | 92.00.6D.00.0A stock -> 92.00.A0.00.03 A100 80GB (see cmp_a100_conversion.md) |
| Stock config | 8 GB / 70 SM |
| **Unlocked config** | **80 GB (81920 MiB) / 128 SM / PCIe Gen3+Gen4 x16** (ECC not burned -- see Remaining work) |

Result verified: GSP boots clean, `nvidia-smi` shows 81920 MiB, CUDA reports
128 SMs / 79.3 GiB usable, memtest_vulkan passed. 128 SM exceeds retail A100
(108 SM) because this die has zero defective GPC/TPC units.

## Method overview

1. **Glitch** the NVVDD rail at the PEX_RST release edge (fuse-sense window)
   to reach the burn-ready state: DSOV=0, SBFE=0, EFP=1, PLMs open.
2. **Enable the write path** (software override + open FUSEWDATA_PLM).
3. **Append FF records** that clear the floorsweep `_DISABLE` masks down to
   the `_DEFECTIVE` masks, plus the PCIe Gen3/4 gates, Gen4 MAGIC_D bits,
   NVLink disable, and the device-ID override (last-record-wins; no physical
   fuse is unblown).
4. **Power-cycle** so the fuse controller replays the new FF chain.

All burns are in the FF region (main-array rows 222-487). Floorsweep
(SM/HBM/PES) and NVLink are chain 1; the PCIe Gen3/4 gates, the Gen4 MAGIC_D
completion and the device-ID override are chain 2. DEBUGCTRL.RWL=0 (main
array, NOT the RIR macro).

## Burn-window prerequisites (checked by ff_burn.py before every write)

| Register | Offset | Required |
|---|---|---|
| FUSECTRL | 0x820000 | IDLE (0xE0040000) |
| CRC_STATUS | 0x820070 | 0x55 |
| DISABLE_SW_OVERRIDE_STATUS (DSOV) | 0x820084 | 0 |
| OPT_SECURED_BURN_FEATURE_ENABLE (SBFE) | 0x821108 | 0 |
| ENABLE_FUSE_PROGRAM_STATUS (EFP) | 0x820078 | 1 |
| FUSEWDATA_PLM | 0x8200F4 | 0xFFFFFFFF |
| FUSECTRL_PLM | 0x8200F8 | 0xFFFFFFFF |
| DEBUGCTRL.RWL | 0x820060 bit1 | 0 |
| target row | - | blank (0x00000000) |

The glitch gives DSOV=0/SBFE=0/EFP=1 and opens FUSECTRL_PLM, but
FUSEWDATA_PLM stays restricted (0xFFFFFF8F) and must be opened each session
(it is volatile; resets on power-cycle).

Reaching this state is out of scope for the burn tools: use a VFI rig of
your choice. The bundled `ga100vfi/` (STM32 PWMVID) and `pico-ga100vfi/`
(RP2350 I2C + PEX_RST) toolchains dip NVVDD across the fuse-sense window at
the PEX_RST release edge and classify the result ("Goldilocks" = DSOV=0,
CRC=0x55, PLMs open); see their READMEs and Kate's write-up (References).

### Enable sequence (each session, after glitching)
```
sudo python3 sw_override.py    --bdf 0000:01:00.0   # EN_SW_OVERRIDE (0x820040) = 1
sudo python3 open_wdata_plm.py --bdf 0000:01:00.0   # OPT_SECURE_FUSE_WDATA_WR_SECURE (0x82048C) = 0
                                                   # -> FUSEWDATA_PLM = 0xFFFFFFFF
```

## FF record format

32-bit record: `(data << 16) | (block << 6) | chain`, bit 5 = 0 (FF).
- bits 0-4: chain (1 = TOP_FS floorsweep)
- bits 6-15: block (block N occupies chain bits 16N..16N+15)
- bits 16-31: 16-bit data

Burn protocol: FUSECTRL=0 -> FUSEADDR=row -> FUSEWDATA=value ->
FUSECTRL=CMD_WRITE(2) -> poll IDLE -> CMD_READ row -> verify. 0->1 only.

### Result after pass 1: GSP BOOT FAILURE
Card failed GSP firmware boot (`failed to wait for GFW boot complete: 0x55`,
progress 0x1) with both stock and cmpunlocker drivers. Cause: SMs were
enabled (GPC/TPC) but **PES and ROP_L2 were still disabled** — these blocks
are required for an SM to function (blog; chain-1 TOP_FS floorsweep includes
PES/ROP_L2). Incomplete record set, not marginal silicon.

## Pass 3 — PCIe Gen3/Gen4 option gates (rows 305-307, chain 2)

Cleared the PCIe generation option fuses so the card advertises Gen3/Gen4
capability. Derived by `ff_derive_pcie.py` (generated plan; records below).

| # | Row | Chain | Block | Old | New | Encoded | Clears |
|---|---|---|---|---|---|---|---|
| 0 | 305 | 2 | 39 | 0x0782 | 0x0580 | 0x058009C2 | DISABLE_GEN3_SPEED (bits 1+9 candidates) |
| 1 | 306 | 2 | 47 | 0x0059 | 0x0051 | 0x00510BC2 | PCIE_MAGIC_BITS_D[25] Gen4 flag |
| 2 | 307 | 2 | 49 | 0x00E4 | 0x0024 | 0x00240C42 | BOOT_GEN23 + BOOT_GEN3 disable |

Verified shadows: OPT_DISABLE_GEN3_SPEED(0x820250)=0, MAGIC_D(0x820520)
bit25=0, BOOT_GEN23(0x82057C)=0, BOOT_GEN3(0x820580)=0. Device Max went 2->4.
Note: the block39 Gen3 bit identity is unresolved (blog: bit1 or bit9); both
were cleared. Capability only -- the link still needs the PHY enable
(Gen2/Gen3 post-GSP sequence + retrain); see cmp_gen3.md.

## Pass 4 — NVLink (row 308, chain 1)

| # | Row | Chain | Block | Old | New | Encoded | Clears |
|---|---|---|---|---|---|---|---|
| 0 | 308 | 1 | 23 | 0x0FEF | 0x0FE8 | 0x0FE805C1 | NVLINK_DISABLE bits 0-2 (SYS_PIPE bits 4-11 preserved) |

## Pass 5 — Gen4 MAGIC_D capability completion (rows 309-310, chain 2)

Gen4 needed more than MAGIC_D bit25. MAGIC_D was 0x14680000 (bits
19,21,22,26,28) vs the A100 reference 0x00200000 (bit21 only): four extra bits
{19,22,26,28}, matching Amogh's "Gen4 needs four fuses." The FF bit->MAGIC_D
mapping is scrambled and undocumented (only bit25->block47 bit3 was known), so
it was DERIVED EMPIRICALLY:

1. Volatile MAGIC_D=0x00200000 (glitch window) lifted LnkCap to Gen4
   (0x00456104), proving the bits gate Gen4 (tools/pcie_gen4_fuse_test.py).
2. Burned block47 -> 0x0000 (row 309): MAGIC_D 0x14680000 -> 0x00280000
   (cleared bits 22,26,28).
3. Burned block46 bit13 (row 310): MAGIC_D 0x00280000 -> 0x00200000
   (cleared bit19).

| # | Row | Chain | Block | Old | New | Encoded | Clears |
|---|---|---|---|---|---|---|---|
| 0 | 309 | 2 | 47 | 0x0051 | 0x0000 | 0x00000BC2 | MAGIC_D bits 22,26,28 |
| 1 | 310 | 2 | 46 | 0xA000 | 0x8000 | 0x80000B82 | MAGIC_D bit19 (block46 bit13) |

Derived with tools/ff_magic_derive.py (live block read + guarded burn).
Result: MAGIC_D = 0x00200000 (A100-exact). This is a THIS-DIE empirical map;
verify with the volatile test before burning another card.

## Pass 6 — Device-ID override for A100 conversion (rows 311-312, chain 2)

Fused device ID 0x20C2 (CMP) -> 0x20B5 (A100 80GB PCIe) so a genuine
NVIDIA-signed A100 ROM passes the boot gate (which checks VBIOS device ID
against the fused ID). FF block stores device_id << 1:
0x20C2<<1 = 0x4184 -> 0x20B5<<1 = 0x416A. Burned via ff_magic_derive.py
(auto blank-row pick); records below are the reference.

| # | Row | Chain | Block | Old | New | Encoded | Changes |
|---|---|---|---|---|---|---|---|
| 0 | 311 | 2 | 37 | 0x4184 | 0x416A | 0x416A0942 | DEVIDA 0x20C2 -> 0x20B5 |
| 1 | 312 | 2 | 38 | 0x4184 | 0x416A | 0x416A0982 | DEVIDB 0x20C2 -> 0x20B5 |

After these burns the card cold-boots and enumerates as 10de:20b5 (A100) with
the CMP VBIOS still on it -- it POSTs but is NOT functional (wrong BIOS for
the fused ID); it IS flashable. Normal in-band nvflash then accepts the
genuine A100 ROM (IDs match); a HW SPI flasher is recommended for
backup/recovery but not required. Full conversion + recovery:
cmp_a100_conversion.md / a100-flash/README.md.

## Reverting (if needed)

FF burns are permanent but reversible by appending restore records
(last-record-wins). `ff_restore.py` derives records carrying the original
block values (from pre-burn `ff.json`) at rows 313+. Re-glitch for the
window, burn the restore records, power-cycle -> stock config.

## Safety rules

- Every burn is IRREVERSIBLE (0->1 OTP). ff_burn.py verifies all prerequisites
  and the read-back; it ABORTS on any failure and never retries.
- Never retry a failed/partial burn (risk of cell damage).
- The burn window (DSOV=0 etc.) is volatile; re-glitch each session.
- DEBUGCTRL.RWL must be 0 for main-array FF burns (RWL=1 routes to RIR macro
  and can wedge the die if left set).
- Burn only blank rows; verify the target row reads 0x00000000 first.

## Remaining work / known limitations (not yet done)

- **Fuse-set completeness**: NOT 100% confident passes 1-6 are all the fuses
  that need burning. They are what this card needed for the observed
  results; other option words (NVDEC, MIG, ...) are untested. A working
  subset, not a proven-complete fuse map.
- **128 SM / full FMA speed are driver-dependent**: the 128 SM result here
  used cmpunlocker TPC/GPC overrides on the CMP VBIOS. With the A100 VBIOS
  the GSP floorsweeps to 124 SM natively; 124 -> 128 needs
  cmpunlocker-a100-minimal --sm-unlock (volatile pre-boot override), and
  full FP32 FMA speed needs its always-on SM_SPEED override EVEN with the
  A100 BIOS -- the SM_SPEED_SELECT throttle fuse is unchanged by the
  conversion.
- **NVLink bring-up**: the NVLINK_DISABLE burn (row 308) is done, but actual
  NVLink still needs the U11 hardware mod + an undocumented ROM-check bypass
  (blog). Bring-up was never tested. The fuse alone is necessary, not
  sufficient.
- **NVDEC / MIG**: additional option words, untested.
- **ECC**: no ECC fuse was ever burned (passes 1-6 cover floorsweep,
  PES/ROP_L2, PCIe gates, NVLink, MAGIC_D, DEVID only). Pre-conversion ECC
  was the cmpunlocker volatile software override; the GPU-side ECC datapath
  is fused off on CMP (cmprir/gpcprobe). Post-conversion ECC is COMPLETELY
  UNVALIDATED AND UNTESTED -- the A100 InfoROM carries the ECC object, but
  nothing here proves ECC works. Do not rely on it.
- **Cooling + sustained validation**: the card was weak-cooled during the PCIe
  work; run extended compute + memory stress and watch for Xid errors. SMs can
  be reduced via cmpunlocker CTRL_OPT_TPC/GPC overrides (volatile, no burn) or
  power/clock limits for heat.

## Final state (A100 conversion)

PCIe Gen3 x16 (13.6 GB/s) and Gen4 x16 (24.7/26.3 GB/s) were both proven via
the post-GSP sequences + retrain. The final permanent conversion is the
device-ID FF override (pass 6) + flashing a genuine NVIDIA-signed A100 80GB
PCIe ROM, giving native Gen4 x16 with correct reporting and 300W. See
cmp_a100_conversion.md / a100-flash/README.md.
