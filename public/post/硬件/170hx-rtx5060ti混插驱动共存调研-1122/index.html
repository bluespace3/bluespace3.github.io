170HX + RTX 5060 Ti 混插·驱动共存调研（2026-11-22）#

起因：计划 2×CMP 170HX + 2×RTX 5060 Ti 混插（有核显平台负责显示输出）。外部 AI 分析判定"能点亮，主要矛盾在驱动版本匹配"。本文为逐条核查后的结论，含两处对原分析的修正。

一、总体判定#

原分析方向正确，机制解释正确，两处细节需修正：

  1. “Linux 仅支持 610.43.03/610.43.02"已过时。 cmpunlocker master（v0.5，driver/VERSION 直读）现支持 6 个版本：610.43.02 / 610.43.03 / 610.57.04 / 615.71.09 / 615.71.10 / 615.78.08。R610 交集不仅存在，窗口比原分析宽得多（610.57.04 是 R610 分支的更新版，615 全系也可选）。
  2. “需要去社区寻找现成魔改包"不成立。 Linux 侧不存在"找包"问题：cmpunlocker 的工作方式就是把官方 nvidia-open 源码打六个补丁本地编译安装，170HX 与 5060 Ti 共享同一套内核模块——open 内核模块自 Turing 起全架构支持、Blackwell（5060 Ti）只支持 open 模块（NVIDIA 官方声明，专有 blob 不支持 Blackwell），两卡天生同栈。Windows 侧 dartraiden/NVIDIA-patcher 的 610.62 patched 驱动官方支持表即为"CMP 与 Turing+ RTX 同用 610.62”，是现成答案，同样无需寻找。

二、共存机制（为什么四卡互不干扰）#

  • 解锁补丁按设备 ID 门控：in-driver device gate 只认 0x20C2（8GB）/0x2082（10GB），补丁代码路径对 5060 Ti 的设备 ID 完全旁路，不会干扰其正常识别（Consensus-Protocol/cmp170hx, install/multi-gpu 文档）。
  • 解锁本身是 per-GPU 的：commit 7fe49b6 起 patched nvidia.ko 内置两套显存 geometry，GSP boot 时按 PCIDeviceID 逐卡现场选择，与安装器记账无关。社区实测：8 张 CMP 170（Proxmox 直通）全解锁；6 卡 rig 用 master 分支运行良好。
  • 但 master 安装器是单卡记账（lspci | head -1）：混 GPU 主机必须显式传 --profile=8gb，否则 profile 可能按 5060 Ti 的显存误检测——已有两起实案（3080 10GB 误判、50HX 被误判成 10GB 170HX）。误判通常只污染 metadata 不影响实际 geometry，但如果非 170HX 卡的显存大小落在所有检测窗口之外，安装会直接中止。

三、本机落点#

  • 现役生产驱动 610.43.02 恰好在解锁窗口内 → 理论上 5060 Ti 可零驱动变更直接并入现役栈。“610.43.02 能否正常点亮 5060 Ti"未实测，是本方案最关键的单点未验证项（见未闭环 #1）。
  • 若目标是现役 9800X3D 生产机：9800X3D 无核显，“有核显"前提不满足，需核实目标机或另配亮机卡。
  • 若进生产机还要一起算三笔账：flashnext 停机窗口（重启贵，测试并入一次加载窗口）、kmine 挖矿 GPU1 让渡现状、PCIe 插槽拓扑（PLX 拓展卡双卡 BAR1 修复有先例笔记）。

四、实装硬前提（驱动之外的物理层）#

项要求出处/理由
BIOS-Above 4G + Resizable BAR必开170HX 解锁后 BAR1=64GB/卡，4 卡约 256GB BAR 空间
Secure Boot必须关补丁模块未签名，install.sh 直接拒绝安装
Primary GPU绝不可设 170HX无显示输出；由核显承担显示
170HX 供电CPU EPS 8pin（250W），须 EPS 转接线矿卡供电规格

电源总额2×250W + 2×180W + 平台余量—

五、Windows 侧备忘（大概率用不上，留档）#

  • dartraiden/NVIDIA-patcher 版本表：CMP 与现代 RTX 同列 = 610.62（Turing+）；Maxwell–Pascal 581.94、更老 472.12。即 610.62 patched 包就是 Windows 侧"四卡同驱动"的解。
  • cmp.wiki 口径提醒：Windows 上"识别可用”（patched driver / NVCleanstall 注入 ID）与"完整解锁”（SM/显存几何）是两回事，后者社区状态 Contested。完整解锁的正路在 Linux GSP 启动路径，无 Windows 对应实现。

六、未闭环#

  1. 610.43.02 + 5060 Ti 点亮验证——决定"零驱动变更并入生产机"是否成立；不成立则评估升 610.57.04（同在解锁窗口内，R610 系）。
  2. 目标承载机未定案：核显来源（哪台机器）；进生产机则停机窗口/挖矿让渡/插槽拓扑三账并算。
  3. 4 卡 BAR1 空间压力（≈256GB Above-4G 窗口）在目标主板上的实际兼容性。
  4. 5060 Ti 用途未定（游戏 / 视频产线 / 第二推理道）→ 影响驱动版本策略与是否需要 16GB 版。
