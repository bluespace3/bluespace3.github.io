2. TAPD 同步三连 Bug 修复（ysbaiautotest 项目）#

  • Bug #1：用例同步报"本地无xxx用例" → 根因：用例库已迁至 Web API，但 TAPD 同步仍读本地 SQLite。修复：改为通过 webTestDataApi 读写
  • Bug #2：标签未同步到 TAPD → 根因：TAPD Labels 要求用标签库数字 UID，而非显示名。修复：新增 search_case_labels / resolve_labels_patch，按 DisplayName 匹配映射

3. 测试策略优化#

💡 深度洞察与经验教训#

  • 洞察：HTTP 200 ≠ 成功。 多个业务接口（订单、理赔）即使业务逻辑失败也返回 HTTP 200，真正的状态藏在业务码 code 里。自动化测试的断言策略必须区分"传输层成功"和"业务层成功"，否则会出现"全绿但没测到东西"的假阳性。

  • 洞察：ID 与显示名是两套体系。 TAPD 标签、分类等引用型字段必须用数字 UID，传显示名会静默失败（返回 200 但不落库）。这类"不报错但没效果"的 Bug 最危险，排查成本远高于直接报错的情况。

  • 教训：数据迁移后，旧读取路径是定时炸弹。 用例库从 SQLite 迁到 Web API 后，TAPD 同步模块仍读本地库，导致"界面能编辑但同步报不存在"。教训：每次数据层迁移，必须全局搜索所有读取点，不能只改增删改入口。

  • 教训：前后端函数签名不一致是最隐蔽的集成 Bug。 fetch_openapi_source 的 doc_sources_path 参数在后端调用处漏传，编译不报错、运行时才炸。Python 的关键字参数机制让它不会 positional 匹配，直接抛 TypeError。接口变更后必须做端到端冒烟测试，单元测试不够。
