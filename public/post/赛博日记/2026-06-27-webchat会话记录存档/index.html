1️⃣ “智能收藏系统"是什么？#

这是你在 3月8-9日 用旧的 OpenClaw workspace（workspace-default）搭建的一个自动收藏+复习系统，核心功能是：

  • 给一个 URL → 自动抓取 → LLM 生成摘要和标签 → 保存为 Markdown
  • 基于艾宾浩斯遗忘曲线定时提醒你复习（1天→2天→4天→7天→15天）
  • 每天 09:30 通过 OpenClaw cron 触发回顾，推送飞书通知

代码在 /root/.openclaw/workspace-default/smart-collect/，是你参考社区提示词搭建的。看起来后来没怎么用，但收藏的几篇文章（如微信公众号的测试框架文章）的回顾记录还留着。

2️⃣ 为什么赛博日记被覆盖成"智能收藏"内容？#

根因是 2026-05-22 的赛博日记 cron 任务（commit c8fa064）。

这个 cron 的 prompt 里要求"搜索 note-gen-sync/ 目录下最近24小时修改的 .md 文件"作为素材。那天的执行中，GLM 模型把旧 workspace 里的智能收藏回顾记录也读进去了，然后不只是在 2026-05-22赛博日记.md 生成日记，还回过头覆盖了 2026-05-16、2026-05-18、2026-05-20、2026-05-21 四篇之前的日记，把原来的正常内容替换成了"智能收藏系统运行日志”。

博客首页展示的短摘要（“智能收藏系统运行日志&mldr;"）就是从这些被覆盖的文件来的。

Tailscale Mac 连接修复 (17:13)#

问题#

  • Mac ([IP]) 的 SSH 和 HTTP 8003 服务通过 Tailscale 无法访问
  • 表现：TCP 连接建立成功，但 SSH 卡在 KEXINIT，HTTP 只返回 header（174 bytes）
  • 根本原因：Tailscale 直连路径 PMTUD 黑洞
    • VPS ([IP]) → Mac ([IP]) 的直连路径上，ICMP Fragmentation Needed 被 ISP/路由器屏蔽
    • WireGuard 封装后的 IP 包超过路径实际 MTU，大包全部丢弃
    • 小包（< ~500 bytes payload）能通，大包丢失

诊断关键#

  • Tailscale ping: 通（240ms）
  • TCP 端口连接: 通
  • HTTP/1.0 小请求: 通但响应体截断（只收到 header 174 bytes，应该收到 6481 bytes）
  • SSH: 卡在 KEXINIT（客户端发出 type 20 后无响应）
  • 局域网: 完全正常

修复方案#

屏蔽 Tailscale 直连，强制走 DERP relay (sea)

  • VPS 端：iptables -I OUTPUT -p udp -d [IP] -j DROP
  • 持久化：/etc/network/if-up.d/iptables-tailscale
  • 效果：Tailscale 自动切换到 DERP relay，虽然延迟略增但连接稳定可靠

注意#

  • Mac 的 IP 可能变化（动态 IP），需要更新 iptables 规则中的目标地址
  • 如果 Mac IP 变了：tailscale status --json 查看 CurAddr，更新 iptables 规则
  • 更好的长期方案：Tailscale ACL 配置 derpMap 强制 relay（需要 Tailscale 管理后台操作）

  • LaunchAgent：com.filemanager.server.plist（KeepAlive=true）
  • 服务本身没挂，只是 Tailscale 路径不通
